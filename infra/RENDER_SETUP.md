# Render.com Backend Setup Runbook

## First-time setup (5 minutes, browser only — no CLI needed)

### 1. Create a Render.com account

- Go to https://render.com → sign up with GitHub.
- Free plan is sufficient for pre-launch.

### 2. Deploy via Blueprint (one click)

1. Dashboard → **New** → **Blueprint**
2. Connect the `patrickgast80/binchen` GitHub repository.
3. Render detects `render.yaml` at the repo root and shows a preview of services:
   - `binchen-postgres` (free Postgres)
   - `binchen-backend` (free Web Service)
4. Review the env vars — `JWT_SECRET` and `COOKIE_SECRET` are auto-generated.
5. Click **Apply** → Render provisions the DB and starts the first Docker build (~5–10 min).

### 3. After first deploy

Once the build finishes and the service is live:

1. In the Render dashboard, find the `binchen-backend` service URL  
   (e.g., `https://binchen-backend.onrender.com`).
2. Go to **Environment** → add/update:
   - `MEDUSA_BACKEND_URL` = `https://binchen-backend.onrender.com`
3. Save → Render redeploys automatically.

### 4. Verify

```bash
curl https://binchen-backend.onrender.com/health
# → {"status":"ok"} with HTTP 200

curl https://binchen-backend.onrender.com/store/products
# → {"products":[], ...} with HTTP 200 (empty until seed)
```

### 5. Post the URL

Paste the backend URL as a comment on [BIL-10](/BIL/issues/BIL-10).  
DevOps will notify Backend and Frontend agents so they wire it into the storefront.

## GitHub Actions integration (auto-deploy on push)

Render's GitHub App triggers a new build on every push to `main` automatically — no extra
secrets needed in GitHub. The `staging.yml` workflow verifies the build first, then Render
picks it up.

Optional: add a Render deploy hook to `staging.yml` to wait for Render's build status:

1. Render dashboard → `binchen-backend` → **Settings** → **Deploy Hook** → copy URL.
2. GitHub repo → **Settings** → **Secrets** → add `RENDER_DEPLOY_HOOK_URL`.
3. Add a step in `staging.yml` after the build:
   ```yaml
   - name: Trigger Render deploy
     run: curl -X POST "${{ secrets.RENDER_DEPLOY_HOOK_URL }}"
   ```

This is optional for v1 — Render's GitHub integration already handles it.

## Rollback

1. Render dashboard → `binchen-backend` → **Deploys** tab.
2. Click the previous successful deploy → **Rollback to this deploy**.

Or with Render CLI:
```bash
npm install -g @render/cli
render deploys list --service binchen-backend
render deploys rollback --service binchen-backend --deploy-id <id>
```

## Environment variables reference

| Variable | Source | Notes |
|---|---|---|
| `DATABASE_URL` | Auto (from `binchen-postgres`) | Never set manually |
| `NODE_ENV` | `production` | Set in `render.yaml` |
| `STORE_CORS` | `https://binchen.vercel.app` | Set in `render.yaml` |
| `ADMIN_CORS` | `https://binchen.vercel.app` | Set in `render.yaml` |
| `AUTH_CORS` | `https://binchen.vercel.app` | Set in `render.yaml` |
| `MEDUSA_BACKEND_URL` | Set after first deploy | e.g. `https://binchen-backend.onrender.com` |
| `JWT_SECRET` | Auto-generated by Render | Rotate after launch |
| `COOKIE_SECRET` | Auto-generated by Render | Rotate after launch |
| `STRIPE_SECRET_KEY` | Set when payment goes live | Stripe dashboard |
| `STRIPE_WEBHOOK_SECRET` | Set when payment goes live | Stripe dashboard |
